1. What is the purpose of CI/CD?
The purpose of CI/CD is to automate the process of integrating code, testing it, and deploying it. This ensures that code changes are regularly checked for errors and can be released quickly and reliably. It helps teams detect bugs early, maintain stable code, and deliver updates faster.

2. How does automating style checks improve project quality?
Automating style checks ensures that all code follows the same formatting and coding standards. Tools automatically detect issues like inconsistent spacing, naming, or structure. This improves readability, reduces confusion between developers, and helps maintain a clean and professional codebase.

3. What are some challenges with enforcing checks in CI/CD?
Some challenges include pipelines failing due to small formatting issues, slower build times from many checks, and developers becoming frustrated when strict rules block their commits. Teams must balance strict quality standards with development speed and productivity.

4. How do CI/CD pipelines differ between small projects and large teams?
Small projects usually have simpler pipelines with basic checks such as linting and unit tests. Large teams often use more complex pipelines that include multiple test stages, security scans, performance tests, and automated deployments to different environments.
